## 2. Документація веб-застосунку
**Призначення:** Сервіс `mywebapp` призначений для створення, зберігання та перегляду текстових нотаток.

**Стек технологій:**
* Backend: Node.js, Express
* База даних: MariaDB (драйвер `mariadb`)
* Взаємодія: REST-подібне API з підтримкою Content-Negotiation (HTML/JSON) залежно від заголовка `Accept`.

**Локальне середовище (Розробка/Тестування):**
1. Встановіть Node.js (v20+) та MariaDB.
2. Виконайте `npm install` у директорії `app/`.
3. Створіть базу даних та виконайте міграцію з файлу `db/init.sql`.
4. Запустіть застосунок командою (приклад):
   ```bash
   node app/server.js --port=3000 --db-host=127.0.0.1 --db-user=root --db-pass=mypass --db-name=notes_db
## 3. API Ендпоінти
Застосунок підтримує повернення даних у форматах `application/json` або `text/html` (залежно від заголовка `Accept`).

* `GET /` — Кореневий ендпоінт. Повертає виключно `text/html` зі списком доступних API.
* `GET /notes` — Отримати список усіх нотаток (повертає масив об'єктів з полями `id`, `title`).
* `POST /notes` — Створити нову нотатку. Очікує JSON body: `{"title": "string", "content": "string"}`.
* `GET /notes/<id>` — Отримати повний вміст нотатки за її ID (`id`, `title`, `content`, `created_at`).
* `GET /health/alive` — Перевірка Liveness (завжди повертає HTTP 200 OK).
* `GET /health/ready` — Перевірка Readiness (перевіряє з'єднання з БД, повертає 200 OK або 500 Error). Заблоковано ззовні через Nginx.

## 5. Інструкція з тестування розгорнутої системи

Після успішного виконання скрипта `setup.sh`, перевірте систему за такими критеріями:

1. **Доступність веб-сервісу:**
   Відкрийте в браузері IP-адресу вашої віртуальної машини (наприклад, `http://<VM_IP>/`). Має відкритися HTML-сторінка зі списком API.
2. **Перевірка Nginx (Reverse Proxy):**
   Спробуйте перейти за адресою `http://<VM_IP>/health/alive`. Nginx має повернути помилку `403 Forbidden` (доступ до системних ендпоінтів ззовні закрито).
3. **Перевірка користувачів та прав:**
    * Спробуйте увійти за користувача `teacher` з паролем `12345678`. Система має негайно запросити зміну пароля.
    * Увійдіть під користувачем `operator` (пароль `12345678`, також вимагає зміни).
    * Виконайте команду `sudo systemctl restart mywebapp` — вона має пройти без запиту пароля.
    * Виконайте команду `sudo rm -rf /` (або іншу адміністративну команду) — система має відмовити в доступі користувачу `operator`.
4. **Перевірка бази даних:**
   Переконайтеся, що створення нотаток працює коректно, відправивши POST-запит на `http://<VM_IP>/notes`.
